# EcoTrack backend: Emissions Management

This first backend increment implements emission sources and activity data in the `emissions` bounded context. It follows the project's domain, application, infrastructure and interfaces package structure. Domain entities enforce invariants, repository ports are implemented with Spring Data JPA, application services coordinate transactions, and REST resources expose the API without serializing JPA entities.

## Run locally

The project currently targets Java 27 in `pom.xml`. Configure a MySQL database and provide `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME` and `SPRING_DATASOURCE_PASSWORD` through the environment or a private local configuration. Do not commit credentials. For example, a URL can be `jdbc:mysql://localhost:3306/ecotrack`.

For an isolated **development** database only, set `SPRING_JPA_HIBERNATE_DDL_AUTO=update` to allow Hibernate to create the tables, then run:

```powershell
.\mvnw.cmd spring-boot:run
```

Do not use automatic schema updates as a production migration strategy. The existing project does not yet provide versioned database migrations. Tests use H2 in memory (test scope only):

```powershell
.\mvnw.cmd test
```

## REST API

All requests and responses use JSON. IDs are generated UUID strings and timestamps are generated by the server.

| Resource | Methods | Optional list filter |
| --- | --- | --- |
| `/api/v1/emission-sources` | POST, GET | `scope=SCOPE_1`, `SCOPE_2`, or `SCOPE_3` |
| `/api/v1/emission-sources/{id}` | GET, PUT, DELETE | — |
| `/api/v1/activity-data` | POST, GET | `emissionSourceId={id}` |
| `/api/v1/activity-data/{id}` | GET, PUT, DELETE | — |

Create or replace a source with:

```json
{
  "facilityId": "facility-lima",
  "facilityName": "Lima Production Plant",
  "name": "Natural gas boiler",
  "type": "Combustion",
  "scope": "SCOPE_1"
}
```

Create or replace activity data for an existing source with:

```json
{
  "emissionSourceId": "<source-id>",
  "period": "2026-11",
  "quantity": 120.5,
  "unit": "kWh",
  "origin": "MANUAL"
}
```

A period must be a valid `YYYY-MM` with a nonzero year; quantity must be positive, with at most 12 integer and six fractional digits. The accepted origins are `MANUAL`, `CSV` and `API`; they identify provenance and do not implement import flows. Updates are full replacements of editable fields and preserve IDs and creation/recording timestamps. Source deletion is rejected with 409 while activity data references it; delete those records first. Creation returns 201 with a Location header, deletion returns 204, invalid requests return 400 and missing records return 404.

## Current limitations

- The organization and facility bounded context is still a scaffold. Facility ID and name are supplied by the client and are not verified against an organization or facility registry.
- Authentication, authorization and organization-level data isolation are not implemented. Do not expose these endpoints or use real organizational data until those controls are in place.
- The frontend still uses its own browser-local demonstration repository; it is not connected to this API.
- Activity values are measurements, not calculated CO2 equivalent emissions. Emission factors, carbon-footprint calculations, CSV import and external integrations are outside this increment.
- The MySQL connection, production migrations and deployment configuration must be supplied and validated for the target environment.
